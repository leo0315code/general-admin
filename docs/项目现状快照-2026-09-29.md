# 项目整体分析（2026-09-29 快照）

> 依据：当前代码实扫（非历史文档）。规模、测试、路由均为本次实测数据。

## 一、一句话结论

**这是一个"功能完整、测试扎实、安全基线在线、但运维与体验层有明确增量空间"的可交付后台模板。**
核心业务（RBAC、字典、文章、用户、导入导出、通知、附件、操作日志）全部落地且有 348 个测试兜底；
剩余问题不再是"缺功能"，而是「工程提效」（队列空转、批量操作、搜索转义、面包屑）与「平台化」（API 层、数据权限、多语言）两类。

## 三、分层架构

```
浏览器
 ├─ Blade 布局（layout + page-header + 分页）
 └─ Vue 3 组件（34 个：表单/列表/弹窗/铃铛/上传器/消息发送器）
        ↓ fetch / XHR（带 CSRF + Accept: json）
Laravel 13（console 前缀路由组）
 ├─ 中间件链：auth → password.changed → permission → SecurityHeaders / LogOperation
 ├─ 授权：Spatie RBAC（菜单即权限，38 菜单 ↔ 35 权限，admin 短路）
 ├─ 服务层：Notifier / Broadcaster / Uploader / WsTicket / OperationLogger / ListQuery
 └─ 数据：18 迁移 / Eloquent（User/Post/Dict*/Menu/Role/Attachment/Notification/Broadcast/Log/Setting）
        ↓
MySQL 8（+ database 队列 / cache）
        ↓
GatewayWorker（WS 推送，可选，关闭时降级轮询）
```

## 六、剩余缺口（按价值排序）

### P1 建议尽快

| # | 项 | 现状 | 风险 |
|---|---|---|---|
| 1 | **附件仍是孤岛** | 无任何业务模块引用 Attachment | 上传功能没人用，`prune` 只会删"没用的文件"；最该做的是接一个真实场景（文章封面/用户头像） |
| 2 | **搜索未转义通配符** | `like "%{$kw}%"` 未转义 `%`/`_` | 用户输入 `%` 会全表匹配；`_` 单字符匹配——小但真实 |

### P2 工程提效

| # | 项 | 现状 |
|---|---|---|
| 3 | **队列空转** | `QUEUE_CONNECTION=database` + jobs 表已建，但零 Job；大批量导入/群发/通知应入队（需先配 worker 文档） |
| 4 | **列表无批量操作** | 排序/筛选/每页条数已有，但无 checkbox 批量（停用/删除/状态切换） |
| 5 | **面包屑缺失** | 全站无 breadcrumb，二级页面返回靠浏览器后退 |
| 6 | **API 层** | `docs/api-layer-plan.md` 已规划未实施（Sanctum token + 速率限制 + /api/v1） |

### P3 长期按需

多语言、部门/组织架构 + 数据权限、监控告警 + 备份恢复演练、平台化（动态菜单/表单/代码生成）。

## 八、质量与工程习惯（本会话沉淀）

- **先计划后动手**、一次一个功能增量推进（P1→P4 驱动）
- 每条 SQL 写操作遵循「预览后确认」工作流
- 组件化优先（"能不用原生就别原生"）、纯函数抽离可单测（useWebSocketEndpoint / useAttachmentFormat）
- 测试即护栏：IconCatalogTest / SeedDataTest 会拦下漏登记的图标与菜单节点
- 性能纪律：未读计数缓存、导航树缓存、批量 insert、FromQuery 流式导出、分页全量白名单
- 本机无风扇，测试降载经验：PHP 用 `--filter` 只跑相关、vitest 用 node 环境 + 串行（36s→4s）
