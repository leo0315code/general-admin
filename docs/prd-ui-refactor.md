## 2. 现状盘点（已核实代码）

基于 `resources/views/layouts/app.blade.php`、`resources/css/app.css`、`resources/views/dashboard.blade.php`、`resources/views/users/index.blade.php`、`roles/index.blade.php`、`menus/index.blade.php`、`layouts/sidebar.blade.php` 与 `vendor/pagination/tailwind.blade.php` 的客观陈述：

1. **已有初步组件基座**：app.css 定义了 `card / card-header / btn-primary / btn-secondary / btn-danger-ghost / btn-ghost / label / input / th / td / stat-card` 共 10 个工具类；暗色模式通过 `.dark` 类 + `localStorage.theme` 全局切换，含防闪烁内联脚本，全站一致性基础良好。
2. **布局为「固定顶栏 h-16（毛玻璃）+ 固定侧边栏 w-64 + 全宽主内容」**，无居中容器；移动端侧边栏抽屉（Alpine `sidebarOpen`）可用。
3. **表格形态统一但为手写重复**：卡片包裹 + `overflow-x-auto` + 灰底表头 + `.th/.td` + hover 行 + 徽章式状态（emerald/red/amber/sky/violet 每种颜色均 inline 手写）；空状态为每页重复的 `@forelse` + 图标 + 文案，无共享组件。
4. **分页为 Laravel 默认 Tailwind 样式**：无每页条数切换、无跳页、无「共 N 条/当前区间」增强；大数据量列表只能逐页翻，体验一般。
5. **破坏性操作全部使用原生 `confirm()`**（删除/停用/启用），交互生硬；项目已有 `modal` 组件（Breeze）但未用于确认场景。
6. **设计 token 薄弱**：无语义色统一变量（success/warning/danger/info），徽章/提示色重复内联；无 loading/skeleton、无 toast 轻提示、无统一空状态组件；图标仅 heroicon，无品牌化图形。
7. **动效与微交互缺失**：页面切换无过渡、按钮仅 hover 变色、无骨架屏、无行级操作反馈；侧边栏分组（目录）不可折叠展开。
8. **响应式与效率细节待加强**：操作列「文字+图标」幽灵按钮在移动端挤压；列表无列排序、无批量勾选、无列筛选；顶栏搜索位为空（`heroicon-o-magnifying-glass` 未挂功能）；表单错误提示为 Breeze 默认单行样式，无 field 级错误态高亮。

**结论**：底子是"功能完整、风格统一但不现代"，主要短板集中在**组件化程度低（重复手写）、动效/反馈缺失、分页与大数据量交互弱、语义色与状态体系未建立**。

## 3. 产品目标（可验收描述）

1. **建立设计系统**：在 `app.css` 的 `@theme` 中沉淀统一 token（语义色 success/warning/danger/info、圆角、阴影、间距、字号），全站 8 个模块的按钮/输入/徽章/表格/弹窗/分页/空状态/加载态均来自同一组件库渲染。
2. **列表页体验现代化**：服务端分页保留，增加「每页条数切换（10/20/50/100）+ 跳页 + 总数/区间显示」；筛选、排序、页码全部 URL 驱动，可刷新/可分享/可回退；大数据量下首屏与翻页流畅不卡死。
3. **交互反馈完整**：破坏性操作统一走确认弹窗（替代原生 confirm）；操作成功/失败有 toast 反馈；页面/弹窗/下拉有 150–300ms 过渡动效；加载中有 skeleton/按钮 loading 占位。
4. **暗色与响应式达标**：暗色模式正文对比度 ≥ WCAG AA（4.5:1），切换无闪烁、可跟随系统；375px 移动端至 1920px 桌面端无横向破版，表格可横向滚动，操作按钮折叠为图标 + tooltip。
5. **可复用脚手架**：沉淀「列表页骨架」「表单页骨架」「确认弹窗」「分页条」「空状态」「状态徽章」等 Blade 组件，新模块开发可直接套用，显著降低重复代码。

## 7. 待确认问题

1. **是否引入第三方组件库（如 daisyUI / Headless UI）？** 建议不引入，继续 Tailwind 原子类 + 自有 Blade 组件，保持轻量与现有风格一致——请架构师确认。
2. **大数据量验收基准：以 10 万行为准是否可以？** 若业务实际量级远小于此（如 <1 万行），PERF-1/2 可降级为 P1。
3. **列表交互增强（列排序/批量勾选/跳页）允许的 JS 形态？** 建议 URL 驱动（服务端排序/筛选）+ Alpine 增强（勾选、跳页、toast），保持无刷新页面回退问题——请架构师确认边界。
